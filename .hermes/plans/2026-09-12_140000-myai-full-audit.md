## 阶段 1: 安全加固 (Critical Security)

### 任务 1.1: 修复 unwrap() 导致的潜在 DoS (Backend)

**目标**: 将生产代码中的 `unwrap()` 和 `panic!` 替换为优雅错误处理

**文件**:
- `Backend/services/api-gateway/src/main.rs:35-47` - 4 个 `unwrap()` (RATE_LIMIT_*)
- `Backend/services/api-gateway/src/main.rs:50-53` - `expect("Failed to connect")`
- `Backend/services/api-gateway/src/main.rs:57-75` - 5 个 `unwrap()` (JWT, CORS)
- `Backend/services/auth-service/src/main.rs:27-38` - 3 个 `unwrap()` (JWT TTL)
- `Backend/services/auth-service/src/main.rs:41-43` - `expect("JWT_SECRET")`
- `Backend/services/browser-service/src/main.rs:44` - `panic!("无法创建...")`

**步骤**:

1. 创建测试文件验证 unwrap 在非法输入时 panic
2. 用 `std::env::var().unwrap_or_else(|_| default)` + `parse().unwrap_or(default)` 替换
3. 对 JWT_SECRET 用 `expect` 改为返回 `Result` 的 `?` 传播
4. 对 browser-service 的 panic 改为返回 `Err` 并优雅关闭

**验证**: `cargo build --package api-gateway --package auth-service --package browser-service` 通过，无 unwrap 在 main.rs

## 阶段 2: 错误处理与稳定性

### 任务 2.1: api-gateway 路由 handler 中的 unwrap 清理

**目标**: 消除 40+ 路由 handler 中的 unwrap()

**文件**: `Backend/services/api-gateway/src/routes/*.rs` (~40 文件)

**步骤**:

1. 用 `grep -rn "unwrap()" Backend/services/api-gateway/src/routes --include="*.rs"` 列出所有位置
2. 对每个 `unwrap()`:
   - 如果是 JSON parse: 返回 `json_error("参数错误")`
   - 如果是 Option: 返回 `json_error("资源不存在")`
   - 如果是 Mutex lock: 用 `map_err` 转为 json_error
3. 运行 `cargo test --package api-gateway`

**验证**: 所有 route 文件中 `unwrap()` 数量 = 0

---

### 任务 2.2: gRPC handler 中的 unwrap 清理

**目标**: 消除服务 handler 中的 unwrap()

**文件**: `Backend/services/*/src/grpc_handlers.rs` 和 `src/handlers.rs`

**步骤**:

1. 对每个 handler 中的 `unwrap()` 和 `expect()`:
   - 用 `map_err(|e| tonic::Status::internal(e.to_string()))` 替换
   - 对 tonic request 字段访问用 `ok_or_else(|| tonic::Status::invalid_argument("xxx"))?`
2. 验证: `cargo build --all-services`

**验证**: 所有 gRPC handler 中无 `unwrap()`

## 风险与权衡

| 风险 | 影响 | 缓解 |
|------|------|------|
| 消除 unwrap 引入大量 Result 传播 | 代码量增加 20-30% | 使用 `?` 操作符 + `thiserror` 派生 |
| 合并 composables 可能破坏现有页面 | 前端回归 | 先写测试再合并 |
| schema.sql 拆分影响现有部署脚本 | 部署失败 | 保留旧文件为 deprecated，渐进迁移 |
| 添加测试减慢开发速度 | 短期效率下降 | 长期减少 bug 修复时间 |
| 端口冲突 (xlt/clean 共用 8095) | 服务无法启动 | 分配新端口并更新文档 |
