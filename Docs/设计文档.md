# MyAI 项目设计文档

> 基于 Rust + Vue 3 + Quasar 的全栈微服务管理平台

## 1. 项目概述

MyAI 是一套面向多业务场景的全栈微服务管理平台，采用 Rust gRPC 微服务架构，提供用户认证、权限管理、审计日志、即时通讯、内容管理、工作流、支付、AI 服务等核心能力。

### 1.1 技术栈

| 层 | 技术 |
|---|---|
| 后端框架 | Rust (Axum) + gRPC (Tonic) |
|| 前端框架 | Vue 3.5 + Quasar 2 + Pinia + Vite（admin 平台 / tenant 单位 / ops 运营 / social 社交） |
|| 数据库 | PostgreSQL（127 表：000_init 103 + 001_saas + 001_tenant_id + 002_index + 003_subscription 5 + gw_tables 7 + 999_reset + schema） |
| 缓存 | Redis |
| 认证 | JWT Bearer |
| 容器化 | Docker / Podman / Kubernetes |
| 部署 | Helm / docker-compose |
| 工程化 | pnpm workspaces + Turborepo |

## 5. 数据库设计

- **表数**: 127 张表（000_init 103 + 001_saas + 001_tenant_id + 002_index + 003_subscription 5 + gw_tables 7 + 999_reset + schema）
- **隔离**: Schema 隔离 + tenant_id 行级隔离（每个服务独立 schema: public, socialops）
- **迁移**: SQLx 编译时验证
- **多租户**: tenant_id 贯穿所有业务表，tenant-core 提供 Schema 路由

## 6. SaaS 多租户架构

### 6.1 隔离模型

MyAI 采用 **共享数据库 + Schema 隔离 + tenant_id 行级隔离** 的混合模型：

- **Schema 隔离**: 不同业务域使用独立 Schema（`public`、`socialops`）
- **行级隔离**: 所有业务表含 `tenant_id` 字段，查询自动附加 `WHERE tenant_id = ?`
- **租户上下文**: 从 JWT 中提取 `tenant_id`，通过 `tenant-core` 中间件注入请求上下文

### 6.2 核心组件

| 组件 | 说明 |
|---|---|
| tenant-service | 租户 CRUD、配额管理、订阅状态 |
| tenant-core | Schema 路由、连接池隔离、查询拦截 |
| tenant_id | int8 类型，贯穿所有业务表 |

### 6.3 租户特定部署

- **共享部署**: 多租户共享同一 K8s 命名空间，通过 tenant_id 隔离
- **专属部署**: 大客户可独占命名空间（租户专属 Helm values）
- **Schema 迁移**: 新租户自动执行 `000_init.sql`（幂等）

## 9. 环境变量

总计 **30+** 个后端运行时环境变量（根目录 .env.example）+ **7** 个构建部署变量（Scripts/.env.example），覆盖：
- 数据库连接（DATABASE_URL）
- Redis 连接（REDIS_URL）
- JWT 配置（JWT_SECRET, JWT_ISSUER, JWT_AUDIENCE）
- 服务端口（*_PORT）
- 限流配置（RATE_LIMIT_*）
- 熔断器配置（CIRCUIT_BREAKER_*）
- 日志级别（RUST_LOG）
- Harbor/Rancher 运维配置（HARBOR_*, RANCHER_*, NAMESPACE）

## 10. 安全配置

- JWT 密钥 ≥ 32 字符
- 数据库 SSL/TLS（sslmode=require）
- CORS 白名单
- Rate Limiting + Circuit Breaker
- 日志脱敏
