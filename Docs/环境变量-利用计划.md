## 2. 目标

1. **消灭虚假声明**：让 .env 机制名副其实（要么实现加载，要么修正文档）
2. **消灭硬编码**：脚本配置统一从 .env 读取，环境变量优先
3. **补齐前端 env**：创建 .env.development / .env.production，与现有 `import.meta.env.VITE_*` fallback 机制衔接
4. **补齐后端本地化**：后端支持 dotenv，本地 `cp .env.example .env` 即可运行
5. **单一事实来源**：`.env.example` 为开发参考模板，`helm values-prod-harbor.yaml` 为生产权威，ENV_MAPPING.md 为两者桥梁

### 阶段2: 脚本层 .env 加载机制（核心，1天）

**改动文件**: `Scripts/lib/env.sh`（新建）+ 8个脚本头部

1. 新建 `Scripts/lib/env.sh`:

```bash
#!/bin/bash
# =============================================================================
# 环境变量加载库
# 优先级: 已存在的环境变量 > Scripts/.env > 脚本内默认值
# 用法: source "$PROJECT_ROOT/Scripts/lib/env.sh" && load_env
# =============================================================================
load_env() {
    local ENV_FILE="${MYAI_ENV_FILE:-$PROJECT_ROOT/Scripts/.env}"
    [[ -f "$ENV_FILE" ]] || return 0
    set -a
    # shellcheck disable=SC1090
    source "$ENV_FILE"
    set +a
}
```

2. 各脚本在 PROJECT_ROOT 解析后追加:
```bash
source "$PROJECT_ROOT/Scripts/lib/env.sh"
load_env
```

3. 硬编码改为 "环境变量优先 + 默认值兜底":
```bash
HARBOR_URL="${HARBOR_URL:-harbor.100.100.100.101.example.com:8003}"
HARBOR_PROJECT="${HARBOR_PROJECT:-erp}"
RANCHER_URL="${RANCHER_URL:-https://100.100.100.101.example.com:8800}"
NAMESPACE="${NAMESPACE:-myai-prod}"
```

4. 更新 `Scripts/.env.example` 补齐 RANCHER_PASS/HARBOR_PASS 注释（密码不入 .env，走交互/密钥文件）

**验证**:
- `bash -n` 全部脚本语法检查
- 无 .env 时行为不变（默认值兜底）
- 有 .env 时 `HARBOR_URL=xx bash ... -t 202608111600 --dry-run` 能读到覆盖值
- 真实跑一次 push/frontend 确认 Harbor 登录仍成功

### 阶段3: 前端 .env 文件补齐（0.5天）

**改动文件**: `Frontend/admin/.env.development` + `.env.production`（新建）

```bash
# .env.development (quasar dev)
VITE_API_BASE_URL=http://localhost:8090/api
VITE_WS_URL=ws://localhost:8090/ws
VITE_APP_TITLE=MyAI Admin (Dev)

# .env.production (quasar build, 构建期注入; 运行时同域 /api 由 Nginx 反代)
VITE_API_BASE_URL=/api
VITE_WS_URL=/ws/messages
VITE_APP_TITLE=MyAI Admin
```

**要点**:
- 现有代码 `import.meta.env.VITE_API_BASE_URL || '/api'` 已兜底，.env 文件是显式化
- 生产走 Nginx 同域反代（`/api` → api-gateway），无需公网 IP 硬编码
- **注意**: 前端构建用 Dockerfile 内 `pnpm build`，.env.production 必须提交 git（不含密钥）

**验证**: `quasar dev` 确认 dev 环境变量生效; `quasar build` 产物中 API 路径为相对 `/api`

## 5. 风险与回滚

| 风险 | 影响 | 缓解 |
|------|------|------|
| .env 加载破坏现有脚本 | 构建/推送失败 | 默认值兜底设计，无 .env 时行为完全不变 |
| .env.production 误提交密钥 | 密钥泄露 | .env.production 只放非敏感 URL，密钥仍走 K8s Secret |
| dotenv 影响生产启动 | 生产配置被本地覆盖 | 显式检测 K8s 环境跳过加载 |
| 前端构建路径变化 | 线上 API 404 | 阶段3 验证产物中 API 路径 |

**回滚**: 所有改动均为增量，git revert 即可恢复；脚本默认值兜底保证任何阶段可安全回退。
